# 逆向き（backward）の共通の決まり（bw-core）

既存の論文を出発点にして research-tree を組み立て直し、確かめ、動かし、直す運用（逆向き）の決まりです。
`professor-backward` と、逆向きのためのブロック（`sci-restore`・`sci-cite-check`・`sci-verify`・`sci-result-compare`）が読みます。
research-tree・木への変更（op）・CARD・実験ループの仕組みは前向き（forward）と同じです。違うのは運用の順番だけです。

## 1. 前向きと逆向き

| 向き               | 出発点                        | 流れ                                                                                     |
| ------------------ | ----------------------------- | ---------------------------------------------------------------------------------------- |
| 前向き（forward）  | 利用者の研究の構想            | SEED（RESEARCH_TYPE と `mind.md`）を決める → PATH を選んで SPROUT を作る → 実験（BRANCH） |
| 逆向き（backward） | 既存の論文（基盤論文）1〜5 本 | 論文から research-tree を復元する → 根拠を確かめる → 論文の手法を再現する → 新しい論文で直す → 比べる |

逆向きでは、研究方針の Q と A は論文に書いてあります。一から考えるのではなく、論文から抜き出して Q・A・F に割り当て、その割り当てと根拠が正しいかを確かめます。

## 2. 5 つの段

| 段              | すること                                                                     | ブロック                                                                                        | 主な成果                           |
| --------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------- |
| 1. 抽出         | 序論を Q と A に、手法を A に割り当てる。結果の数値を記載結果表にする | `sci-restore`                                                                                   | 復元書                             |
| 2. 評価（引用） | 主張ごとに引用文献を取り寄せ、根拠になっているかを判定する                   | `sci-cite-check`                                                                                | 引用の判定表                       |
| 2. 評価（research-tree）   | 復元した research-tree を CRITERIA（§10）で審査する                                       | `sci-verify`                                                                               | 審査書                             |
| 3. 再現         | PATH を選んで再現の SPROUT を作り、論文の手法を E として動かす                                        | `sci-exp-sprout`                                                                                  | 再現の SPROUT・完了報告書（再現）   |
| 4. 更新         | 新しい論文を探して A を直し、更新の SPROUT を作って動かす                   | `lab-search`・`lab-read`・`lab-grow`・`sci-verify`・`sci-exp-sprout` | 更新の SPROUT・完了報告書（更新） |
| 5. 比較         | 論文の記載・再現・更新を COMPARISON_CRITERIA（§11）で比べる                  | `sci-result-compare`                                                                            | 比較書                             |

## 3. 基盤論文

- 基盤論文は Library の番号で指定します。依頼文や CARD の目的に `基盤論文: #12 #15` の形で書きます。
- 本文が読めること（`sai-paper content outline` が返ること）が前提です。読むときは `sai-paper content outline <番号>` で節を選び、`sai-paper content read <節の ID>` で読みます。読めないときは `perl -e 'alarm 600; exec @ARGV' sai-paper paper citations-extract <番号>` で本文と引用を抜き出してから読みます（`sai-paper paper extract` は Library の番号ではなく S2 の ID を取るので使わない）。それでも読めなければ、その論文は抽出の対象から外し、report に書きます。
- 2 本以上のときは、最初に関係を 1 つに決めます。
  - **一連の研究**: 前の論文の手法を、後の論文が直している。後の論文ほど新しい決定として扱い、前の論文の答えは A（`add_a`）として残す。
  - **同じ型の研究**: 同じ課題を別の手法で解いている。手法を A として並べ、どれを再現の対象にするかは professor が Human に聞いて決める。

## 4. 論文の節と Q の対応

| 論文の節                                   | research-tree での置き場                                           |
| ------------------------------------------ | ------------------------------------------------------ |
| 序論の背景・動機                           | SEED（`mind.md`）の文脈（`## ORIGIN` に書く）    |
| 序論の対象                                 | Q（誰・何を対象にするか）                              |
| 序論の目的・貢献の一覧                     | Q（何を明らかにするか）。貢献の主張は A                |
| 序論の先行研究・関連研究                   | 先行研究の F（`cites` に基盤論文の場所）               |
| 序論の「既存の手法は〜ができない」         | Issue の A（未解決の課題）。利用者が Issue に切り替える |
| 貢献の主張（「本研究は初めて〜」）         | A                                                      |
| 手法                                       | A（手法の候補）と、その根拠の F                        |
| 実験の設定（データ・分割・前処理・ラベル） | Q（データは何か）の A と F                             |
| 評価指標と比べる相手                       | Q（何で測るか）の A。実験ループが指標と成功基準を読む  |
| 結果の表・図                               | 記載結果表（§8。research-tree には入れず、比較の材料にする）       |
| 限界・今後の課題                           | 更新の材料（`add_q` で Q にする）                      |

- 該当する Q が無いときは、`add_q`（許可を取ってから出します）で足します。指標の Q が無いと、実験ループ（`sci-exp-sprout`・`sci-exp-review`）が指標と成功基準を読めません。
- 論文の型が今の research-tree の型と違うときは、利用者に Web で research-tree を始め直してもらう文として示します。自分では `sai-sci init` を打ちません。

## 5. 主張は A、根拠は F

基盤論文に書いてある文は**主張**です。基盤論文は、自分の主張の証拠になりません。

- 基盤論文の主張は A にします。`add_a` の文を「主張: 」で始め、根拠として F（`add_f`）を付けます。F の `cites` に基盤論文の場所（塊の ID `#12.3.2`）を書きます。
- 引用文献を読んで分かった F は、引用文献の塊の ID（`#40.4.2`）を `cites` に書きます。主張を支える F か、主張に反する F かは、`stance`（`support` か `deny`）で書きます。
- - 仮の決定は使いません。評価で崩れた主張は、A と F の文で崩れた理由を書き、利用者に伝えます。

## 6. 主張と引用の対応表

復元書（`sci-restore` の report）に必ず入れる表です。評価（引用）はこの表を入力にします。

```markdown
| 主張 | Node | 基盤論文の場所   | 主張（1 文）                             | 引用の番号 | Library の番号 |
| ---- | ---- | ---------------- | ---------------------------------------- | ---------- | -------------- |
| C1   | A12  | #12.3.2           | 頭皮脳波による発作起始の推定は精度が低い | [3], [7]   | #40, 未取得    |
| C2   | A15  | #12.4            | 既存の手法は長い記録で精度が落ちる       | なし       | ―              |
```

- 引用の番号と引用文は `sai-paper paper citations <基盤論文の番号>` で取ります。`refs[].ref_no` が引用の番号、`refs[].sentences` がその引用を使っている文、`refs[].local_paper_id` が Library の番号（未取得なら `null`）です。`extracted` が `false` なら、先に `perl -e 'alarm 300; exec @ARGV' sai-paper paper citations-extract <基盤論文の番号>` を打ちます。
- 引用の無い主張も必ず書きます（引用の番号は「なし」）。根拠が足りない主張です。
- 主張の ID（`C1`…）は復元書の中だけの通し番号です。他の文書から指すときは「C3（復元書 `waggle:<トークン>`）」と書きます。

## 7. 引用の判定

| 判定   | 意味                                                         | F の扱い                                 |
| ------ | ------------------------------------------------------------ | ---------------------------------------- |
| 支持   | 引用文献が主張をそのまま示している                           | 主張を支える F として出す                |
| 部分   | 対象・条件・数値の一部が主張と違う                           | 支える F として出し、違いを F の文に書く |
| 無関係 | 引用文献に、主張に当たる記述が無い                           | F は出さない。表にだけ残す               |
| 反証   | 引用文献が主張と逆のことを示している                         | 主張に反する F として出す                |
| 孫引き | 引用文献も、別の文献を引いて述べているだけ                   | F は出さない。表にだけ残す               |
| 未確認 | 本文が手に入らない（抄録だけ・入手できない）                 | F は出さない。表にだけ残す               |

- 抄録しか読めなかったときは「未確認（抄録のみ）」とし、抄録で分かったことだけを書きます。抄録で「支持」とは判定しません。

## 8. 記載結果表

```markdown
| 結果 | 手法     | データ・分割                 | 指標 | 値   | ばらつき      | 場所        |
| ---- | -------- | ---------------------------- | ---- | ---- | ------------- | ----------- |
| R1 ★ | 提案手法 | 公開データ A・5 分割交差検証 | AUC  | 0.87 | ±0.01（5 回） | #12 Table 2 |
| R2   | 基準線 B | 同上                         | AUC  | 0.81 | 記載なし      | #12 Table 2 |
```

- 値・ばらつき・回数は、論文に書いてあるものだけを書きます。無ければ「記載なし」。
- 再現で狙う主な結果に ★ を付けます（1〜2 個）。
- ablation（成分を外した結果）も行にします。再現と比較で「傾向が同じか」を見る材料になります。

## 9. 再現の SPROUT

再現のときは、`sci-exp-sprout` が復元書から PATH を選んで再現の SPROUT を作ります。そのとき `sci-exp-sprout` に渡す文書に、次の「## 再現の決まり」を足します。

```markdown
## 再現の決まり
### 論文の設定
| 設定 | 値 | 場所 |
### 論文に無い設定（仮に置く値）
| 設定 | 仮の値 | 理由 |
### 狙う値
記載結果表の ★ の行（値・ばらつき・場所）。許容幅は Human が決める（決まるまでは「未定」）。
### 公開されているもの
コード・データ・学習済みの重みの場所（論文に書いてある URL だけ。無ければ「記載なし」）。
### 再現で守ること
- 世代 1 の `draft` は、論文の手法と設定をそのまま書く。基準線を簡単にしない。
- `tune` で動かしてよいのは「論文に無い設定」だけ。論文に書いてある値は変えない。
- 論文と違う手法を試さない（`new` は再現の外）。
```

## 10. CRITERIA（V）

`sci-verify` が審査し、professor が評価の段の終わりを決める材料にします。基準は足してよいですが、減らしません。

| ID  | 問い                                                                                                        | 主な材料                           |
| --- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| V1  | 復元した Q・A の値は、論文の記述と一致しているか（言い換えで意味が変わっていないか）                          | 主張の A と F・基盤論文の本文      |
| V2  | Q・A・F への割り当ては、ガイドの定義に合っているか（課題と目的の取り違えなど）                              | `# context` の `## GUIDE`                 |
| V3  | 主張ごとの根拠は足りているか（引用なし・無関係・孫引き・未確認が多い A）                                  | 引用の判定表                       |
| V4  | 主張に反する論文は無いか（反証を探したか）                                                                  | 反証の F・`lab-search` の report  |
| V5  | 復元した SEED から STAR_PATH は正しいか（課題の原因 Issue の A に手法が効く筋か。論文は他の手法の案と比べたか） | Issue の A・手法の A・復元書      |
| V6  | SEED から E は十分に試されているか（ablation・設定の幅・データの違い・基準線の数）                     | 記載結果表・手法の節               |
| V7  | 評価のしかたは妥当か（指標の計算・分割・漏洩・基準線の選び方・試行の回数）                                  | 指標の Q・記載結果表       |
| V8  | 新規性は保たれているか（最も近い研究の抜け・発表後の研究で失われていないか）                                | 新規性の A・検索の記録            |
| V9  | 再現に要る情報は論文に書いてあるか（論文に無い設定の数と重さ）                                              | 再現の決まりの「論文に無い設定」 |
| V10 | 基盤論文どうしで食い違いは無いか（2 本以上のとき）                                                          | 主張の A と F                     |

判定は「良」「要補強」「誤り」「判定できない」の 4 つです。点数は付けません。各基準に、根拠（F の ID・主張の ID）と、Next Action（ブロック・Node・目的）を書きます。

## 11. COMPARISON_CRITERIA（K）

`sci-result-compare` が比べます。基準は足してよいですが、減らしません。

| ID  | 問い                                                                                                       | 主な材料                             |
| --- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| K1  | 再現の値は、論文の記載値（★）と許容幅の中で一致しているか。外れたら差はいくつか                            | 記載結果表・完了報告書（再現）・台帳 |
| K2  | 数値が合わなくても、傾向（手法の順位・ablation の向き）は論文と同じか                                      | 記載結果表・台帳                     |
| K3  | 再現と論文の条件の差は何か（データ・分割・前処理・乱数・計算資源・仮に置いた設定）。差の原因の候補はどれか | 再現の決まり・実験仕様書        |
| K4  | 更新の手法と論文の手法は、同じデータ・分割・指標・試行の回数で比べているか（公平さ）                       | 実験仕様書（再現・更新）             |
| K5  | 更新の手法は論文の手法より優れているか。差はばらつきより大きいか（試行が 1 回だけなら「確かめられない」）  | 台帳・MLflow                         |
| K6  | 費用（実行時間・計算資源）はどう違うか                                                                     | 台帳の `exec_time_s`・MLflow         |
| K7  | 論文の主張（C の ID）のうち、どれが支えられ、どれが弱まったか                                              | 主張と引用の対応表・引用の判定表     |
| K8  | 残った Q は何か（次の更新の SEED になるもの）                                                                 | 上の全部                             |

- 数値は台帳（`exp_summary.py`）・完了報告書・MLflow の値だけを使います。自分で計算し直しません。差の計算も、材料の値を並べて引き算するだけにし、式を書きます。

## 12. 文書の名前

| 文書           | `--filename`                         | `--description`                                   |
| -------------- | ---------------------------------- | ----------------------------------------------- |
| 復元書         | `sci-restore-<短い英字>.md`        | `復元書: <基盤論文の番号>: <1 文>`              |
| 再現の決まり  | `sci-restore-repro-<短い英字>.md`  | `再現の決まり: <基盤論文の番号>: <1 文>` |
| 引用の判定表   | `sci-cite-check-<短い英字>.md`     | `引用の判定表: <主張の範囲>: <1 文>`            |
| 審査書         | `sci-verify-<短い英字>.md`    | `審査書: <基盤論文の番号>: <1 文>`              |
| 比較書         | `sci-result-compare-<短い英字>.md` | `比較書: <study の名>: <1 文>`                  |

## 13. 迎合しない

- 基盤論文に不利なことを伏せません。よく引かれる論文でも、根拠の弱い主張は弱いと書きます。
- 再現できなかったことも成果です。「合わせるための変更」をして一致させません。
- 事実（論文・引用文献・実験の記録に書いてあること）と解釈（あなたの考え）を分けて書きます。
