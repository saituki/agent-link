# 統計解析の決まり（stat-core）

`sci-data-test` が読む統計解析の決まりである。**`data-core` と必ず一緒に読むこと。** データ表・前処理・EDA・MLflow の記録・research-tree への置き方は `data-core` にある。データ表の書式は `data-core` §4、生体信号の EDA は `data-core` §7、実験の流れへの委任は `data-core` §11 から引く。同じことをここで繰り返さない。

この文書の **§1 の解析計画・§11 の `results.json` と検査・§12 の書式は共有契約**であり、`sci-data-test` ブロックも道具 `data_result.py` もこれを書き換えない。

## 1. 解析計画書

- 解析を動かす**前に**、解析計画 `plan.json` を `analysis/<study>/ID<自分の run_id>/plan.json` に書き、**同じ JSON を本文の先頭に置いた解析計画書**を `sai-link doc write` で保存する。ファイル名 `ana-plan-<study>-ID<run_id>.md`、description `解析計画書 <study> ID<run_id>: <主な仮説を 1 文で>`。返ってきた **waggle トークンを控える。**
- **順序は守る（計画 → 保存 → 解析）。** 結果を先に見てから計画を書くと、計画は結果の言い換えになる。
- 仮説の出どころは 3 つだけである。CARD の Node の A、seed（D）、データ表の「解析の候補」。**ここから出ない仮説は探索的**である。
- `kind: confirmatory` は事前に決めた主な仮説だけ（**多くても 3〜5 個**）。それ以外は `exploratory`。

各仮説で決めること（`plan.json` の 1 つ 1 つの `hypotheses` の要素に対応）。

| 決めること | 入れる欄 | 決めかた |
|---|---|---|
| 結果の変数と説明の変数 | `outcome`・`predictor` | 列名。データ表に無い列は使わない |
| 観測の単位 | `unit` | `subject`（人）か `trial`（試行）か。同じ人の繰り返しは独立ではない |
| 検定 | `test` | §2 の決定木。書き方は §1 のとおり |
| 片側か両側か | `alternative` | 向きのある仮説を事前に決めたときだけ片側 |
| 属する family と補正 | `family`・`families[].correction` | §4 |
| 効果量と SESOI | `effect`・`sesoi` | §5。**SESOI は「意味のある最小の効果」**。慣習の目安で埋めない |
| 確かめる前提 | `assumptions` | §3 |
| 外れたときの代わりの検定 | `fallback` | §3。**計画に書いておくことが先決**である |

- `families` には、同じ問いへの検定の集まりだけを入れる。別の問いは別の family にする。
- 計画を保存したあとで変えたくなったら、**計画は書き換えない。** 結果の `deviation` に理由と変えた点を書き、その結果は**探索的として報告する**（K3・K4）。
- `plan.json` の全文:

```json
{"study": "A6-ID130", "run_id": 131, "data_card": "AbCdEf12",
 "created_at": "2026-10-04T12:00:00+09:00", "alpha": 0.05, "seed": 20261004,
 "hypotheses": [
   {"id": "H1", "kind": "confirmatory", "question": "刺激群は対照群より RMSSD が高い",
    "outcome": "rmssd", "predictor": "group", "unit": "subject",
    "paradigm": "frequentist", "test": "welch_t", "alternative": "greater",
    "family": "F1", "effect": "hedges_g", "sesoi": 0.3,
    "assumptions": ["independence", "normality_of_residuals"], "fallback": "mann_whitney_u"}],
 "families": [{"id": "F1", "correction": "holm", "members": ["H1", "H2"]}]}
```

- この例は紙面のため仮説 H1 だけを載せる。H2（bayes）・H3（ml）も同じ形で `hypotheses` に書き、`families.members` の H2 はそのうち計画にある仮説だけにする。
- `data_card` にはデータ表の waggle トークンを書く。`alpha` と `seed` は 1 つの解析全体で 1 つに決めて、変えない。
- 解析スクリプト `analysis.py` は PEP 723 の欄を先頭に置き、`dependencies` に**版を固定して**書く。使うものだけを書く。

  ```python
  # /// script
  # requires-python = ">=3.11"
  # dependencies = ["numpy==2.1.0", "pandas==2.2.3", "scipy==1.14.1", "pingouin==0.5.5", "statsmodels==0.14.4", "matplotlib==3.9.2"]
  # ///
  ```

出典: K-Dense `statistical-analysis`（事前登録・解析の流れ）

## 2. 検定の選び方

### 先に決めること

1. **何を推定したいか**（平均の差・比率・関連・予測）。このあと何を書くと意味のあるかの基準になる。
2. **観測の単位と独立性**。同じ人の繰り返しは独立ではない（擬似反復）。反復は群の中ではなく人の間で取る。
3. **データの型**（連続・順序・二値・数え上げ）。
4. **群の数と対応の有無**。同じ人か別人かが分かると、検定が決まる。

### 決定木

| 設計 | 推定したいもの | 選ぶ検定 |
|---|---|---|
| 2 群・独立・連続 | 平均の差 | **Welch の t 検定（既定）**。等分散を仮定する Student の t は、共通分散を理由があるときに限る |
| 2 群・独立・連続 | 分布・順位の差 | Mann-Whitney U。**中央値の差の解釈には分布の形が比較できることが要る** |
| 2 群・独立・二値 | 比率の差 | カイ二乗。**期待度数が 5 未満なら Fisher の正確検定** |
| 2 群・独立・順序 | 順位の差 | Mann-Whitney U |
| 2 群・対応あり | 平均の差 | **対応のある t 検定**。差の分布を見る（正規性は対の差について確かめる） |
| 2 群・対応あり | 差の中央値 | Wilcoxon の符号順位（**差が対称のとき**）。対称でなければ符号検定 |
| 2 群・対応あり・二値 | 比率の差 | McNemar の検定 |
| 3 群以上・独立 | 平均の差 | **Welch の ANOVA（既定）**。等分散を仮定する一元 ANOVA は、理由があるとき |
| 3 群以上・独立 | 順位の差 | Kruskal-Wallis の H 検定。中央値の解釈には形の比較が要る |
| 3 群以上・独立・二値 | 比率の差 | カイ二乗 |
| 3 群以上・対応あり | 平均の差 | 反復測定 ANOVA（球面性の補正つき）か混合モデル（§6） |
| 3 群以上・対応あり | 順位の差 | Friedman の検定。欠けや回数が違うときはモデルが必要 |
| 要因が複数 | 要因の主効果・交互作用 | 二元 ANOVA、より高次の ANOVA |
| 要因が複数・説明変数がある | 群の効果を説明変数で調整して比べる | ANCOVA |
| 要因が複数・同じ人が繰り返す | 主効果・交互作用 | 混合 ANOVA |
| 2 変数の関連（連続） | 線形の関連 | Pearson の r |
| 2 変数の関連（順序・非線形） | 単調の関連 | Spearman の ρ（順位データなら Kendall の τ） |
| 生存時間 | 生存曲線の差 | 対数順位検定。説明変数があれば Cox の比例ハザード |
| 一致と信頼性 | 評価者間の一致 | カテゴリ 2 人なら Cohen の κ、3 人以上なら Fleiss の κ か Krippendorff の α。連続値なら **ICC** |
| 検査再測定 | 再測定の信頼性 | **ICC**（一致か一貫性・1 人か平均・評価者が変量か固定かを書いて選ぶ）。Pearson の r は一致の指標ではない |
| 方法どうしの差 | 一致 | 連続値なら Bland-Altman 分析 |

- **Shapiro-Wilk や Levene の p 値だけで検定を切り替えない。** 前提の検定に頼る切り替えは誤りを増やす。前提は図と設計で判断する（§3）。
- 決定木に無い設計（数え上げ・生存・反復測・信頼性）は、計画に書いたうえで `test` に小文字の識別子を置いてよい。
- 実装に使うライブラリの版は PEP 723 の欄で固定する。ふつうは `scipy.stats`（基本の検定）・`pingouin`（効果量が一緒に返る）・`statsmodels`（回帰・診断・検出力）。

出典: K-Dense `statistical-analysis`（検定の選択の決定木）・`experimental-design`（Fisher の 3 原則と擬似反復）

## 3. 前提の確かめと、外れたとき

### 確かめるもの

| 前提 | 確かめかた |
|---|---|
| 独立性 | **設計で判断する。** 図や表からは分からない。群が人ごとに分かれているか、1 人の測定が別人の測定の独立な複製か |
| 残差の正規性 | QQ プロット。群ごと、対応のある設計では差について見る |
| 等分散 | 箱ひげと残差対予測値の図 |
| 線形性 | 散布図と残差図 |
| 外れ値の影響 | **外したときと外さないときの両方を見る。** 外すのは計画に規則があるときだけ（§13） |

- Shapiro-Wilk や Levene の**非棄却は「満たしている」証明ではない。**
- **大きな標本では小さなずれでも有意になり、小さな標本では検出できない。** 「n が 30 になったら正規性の前提が不要になる」という一律の決まりは無い。分布の裾・偏り・群の大きさの偏り・独立性・推定したい量で判断する。
- 独立性はこの道具では確かめられない。設計のレビューで確かめる。

### 外れたときの選び方

| 状況 | 選び方 | 注意 |
|---|---|---|
| 等分散が疑わしい | Welch の t / Welch の ANOVA / Games-Howell の対比 | **最初から Welch を使っておく**のがいちばん確実 |
| 差の分布が歪む・外れ値に敏感 | 順位の検定（Mann-Whitney・Wilcoxon・Friedman） | **問いが変わる**。分布の差を問うなら道具は合うが、中央値の差の主張には形の比較が要る |
| 変換できそう | 対数・逆・平方根の変換 | **変換したら結果の変数の単位が変わる。** 変換の式と解釈の変化を書く |
| 不等分散だけがある | 頑健な標準誤差（HC3） | **不均質分散には効くが、クラスタや交絡、平均モデルの誤りは直さない** |
| 観測が入れ子・繰り返す | 混合モデル（§6） | 人を変量効果にして独立性を表す |
| 何の仮定も当てにできない | ブートストラップの CI | 反復回数と種を書く（§5） |

### 結果への書き方

- `results.json` の `assumptions` に、確かめた前提ごとに `name`・`method`（使った検査。例 `qq`）・`ok`（前提が満たされたか）・`note` を書く。
- `fallback` に替えたときは、**外れた前提を `ok: false` で書く**（K4）。外れなかった場合は書かない。
- 替えた理由と、その結果がどう変わるかを `deviation` に書く。

出典: K-Dense `statistical-analysis`（前提と診断）・`statsmodels`

## 4. 多重比較

- **family（同じ問いへの検定の集まり）を計画のときに決める。** `plan.json` の `families` に `id`・`correction`・`members` を書く。
- family の中の検定が 2 つ以上なら**必ず補正する。** 補正後は `p_adj` に書く（K6）。補正後の p が `p_adj >= p` にならないと検査で弾かれる。

| 場面 | 補正 | 理由 |
|---|---|---|
| ANOVA のあとの全ての対の比較 | `tukey`（Tukey HSD） | 全対の比較向けの補正。等分散を仮定しない設計では Games-Howell を使う |
| それ以外の family（2〜10 個程度） | `holm`（既定） | Bonferroni より強く、仮定が要らない |
| 数が多く、探索的な検定 | `bh`（Benjamini-Hochberg、誤検出率の制御） | すべての真の仮説を厳密に数えるのは現実でないとき |
| Bonferroni（`bonferroni`） | **理由があるときだけ** | Holm より弱い。同じ結論なら Holm を使う |

- 補正したかどうかを**必ず書く。** 読者が「補正なしの多数の p 値」と区別できるようにするためである。
- **してはいけないこと**: 有意になるまで部分集団を探す / 結果の変数を取り替える / 補正をしないで多数の検定を報告する。
- 1 つの family に、属する検定が 1 つだけなら補正は要らない（`correction: "none"`）。
- 独立な 20 個の検定をすべて帰無仮説の下で行うと、少なくとも 1 つが誤って棄却される確率は約 64% になる。検定どうしの従属関係は独立な場合より小さいが、無視して補正を省いてはならない。

出典: K-Dense `statistical-analysis`（多重比較）・`scientific-critical-thinking`（多重比較の落とし穴）

## 5. 効果量・信頼区間・検出力

- **すべての確証的な検定で、効果量とその 95% 信頼区間を報告する。** p 値だけで終わらせない。p 値は「帰無のモデルとの矛盾の程度」であり、効果の推定値とその不確かさが判断の材料になる。

| 効果量 | 使う場面 | 小 | 中 | 大 |
|---|---|---|---|---|
| Cohen の d | 2 群の平均の差 | 0.20 | 0.50 | 0.80 |
| Hedges の g | Cohen の d の小さな標本での補正版（`plan.json` の `effect` の既定） | 同上 | 同上 | 同上 |
| Glass の Δ | 対照群の標準偏差で割る（対照群のばらつきが大きいとき） | | | |
| 偏 η²（`η²_p`） | ANOVA・回帰 | 0.01 | 0.06 | 0.14 |
| ω² | 標本が小さいときの η² の補正版 | | | |
| r | 相関 | 0.10 | 0.30 | 0.50 |
| Cohen の f | ANOVA の検出力（η² から変換） | 0.10 | 0.25 | 0.40 |
| Cramér の V | 2×2 の表 | 0.10 | 0.30 | 0.50 |
| オッズ比 | 二値の結果（1 を超えると正の関連） | | | |
| R² | 回帰 | 0.02 | 0.13 | 0.26 |

- **この表の目安は慣習であって法則ではない。** 薬効の副作用のように「小さい」効果が重大なこともある。**分野の SESOI を優先する。**
- CI の求め方: `pingouin.compute_effsize` で点推定を、`pg.compute_esci` でその CI を求める（`pg.compute_effsize_from_t` は点推定しか返さない）。標本の大きさは、欠損の扱いを決めたあとの分析後の数を使う。この CI は近似であり、不均質分散のときの標準化効果の保証ではない。ブートストラップなら反復回数と種を書く。
- **検出力は計画のとき（事前）に求める。** SESOI から「何人にすればよいか」を `statsmodels.stats.power` で出し、効果量の候補が幅を持つときは**感度分析**（複数の効果量で n を出し直す）を添える。効果量の数値を作り出さない。
- **終わったあとは感度分析を書く**（この n で 80% の検出力で見つけられる最小の効果 = MDE）。
- **観測した効果量から検出力を計算すること（事後の検出力）はしない。** 観測した効果量から求めた検出力は p 値の言い換えで、情報が無い。求められても、その問題点を指摘したうえで数値を書かない。
- 複雑な設計（混合モデル・ロジスティック・クラスタ割り付け）の検出力は**シミュレーション**で求める。1 回に 1,000 回以上、80% の近くを安定させるには 5,000 回以上。**モンテカルロの CI を一緒に書く**（シミュレーションの誤差が分かる）。
- **「有意でない」は「効果が無い」ではない。** 小さい標本では効果があっても検出できない。同等性を言いたいなら**同等性の検定（TOST）**を計画のときに書く。TOST は「差が SESOI の幅に収まる」ことを示すが、「効果が無い」ことを示すものではない。

出典: K-Dense `statistical-analysis`（効果量）・`statistical-power`（検出力と効果量）

## 6. 回帰とモデル

### 選び方

| 結果の変数 | モデル | 補足 |
|---|---|---|
| 連続 | OLS（通常最小二乗） | 非線形なら多項式や GAM |
| 二値 | ロジスティック | 希少な事象なら exact か Firth の補正 |
| 数え上げ | ポアソン、ばらつきが大きければ負の二項 | 零が多いだけではゼロ膨張を正当化しない |
| 繰り返し・入れ子 | 混合モデル（`statsmodels` の `mixedlm`） | 人や試行を変量効果にする |
| 時系列 | 状態空間・ARIMA など | §7。**ARIMA の中で先に差分を取らない**（二重の差分になる） |
| 生存時間 | Cox の比例ハザード、Weibull など | 比例ハザードの前提を確かめる |

- 切片の指定: 配列の API では定数を自分で足す（`sm.add_constant`）。formula の API は自動で入る。順序付きモデル **`OrderedModel`** は定数を入れない。
- 欠損は `missing="raise"` にして明示的に扱う。行を落とすときは残した行の ID を記録し、**同じ観測でモデルを比べる。** 補完は学習側のデータの範囲で行う。

### 確かめること

- 残差対予測値の図・QQ プロット・多重共線性（VIF）・**Cook の距離**で影響の大きい点。
- 係数の解釈は単位と中心化を押さえて書く。対数リンクなら指数化（`exp(β)`）した値も書く。
- モデルの比較は **AIC・BIC が使えるのは、同じデータの同じ結果の変数で比べるときだけ。** 入れ子のモデルは尤度比検定で比べる。
- **予測の良さを言うときは交差検証（§8）。** 説明（推定）と予測を混ぜない。
- **交絡を言うときは、どの変数で調整したかと、その理由（因果の図）を書く。** 調整したからと言って因果とは言えない。「X は有意でなかったから交絡ではない」とは言えない。有意でない変数を調整に入れるかどうかと、その変数が交絡であるかどうかは別の話である。
- 頑健な標準誤差（HC3）は**不均質分散**には効くが、クラスタ・交絡・平均モデルの誤りは直さない。
- 最適化警告（収束していない）が出たら使わない。

出典: K-Dense `statsmodels`（回帰と診断）

## 7. 時系列・生体信号の解析

### 時系列の決まり

- **時系列の観測は独立でない。** 隣り合う点が同じ内容を表す。自己相関を確かめる（残差対ラグの図、Durbin-Watson は記述的な値）。**ふつうの t 検定を時点ごとに繰り返さない。**
- **人ごとに指標を 1 つにまとめてから群を比べる**（擬似反復を避ける）か、**混合モデルで人を変量効果にする**か、どちらかを計画に書く。
- 記録の長さが人によって違うときは、同じ幅で切り出して揃えるか、記録の長さを共変量にする。短い記録を長い記録と同じものとして平均しない。
- 欠測は、落ちた値と「測定しなかった値」を区別して数える。

### 生体信号の決まり

- **解析の型で指標が変わる。** イベントに結び付いた解析（刺激ごとの反応）か、区間の解析（安静時の記録全体）かを先に決める（型と道具は `data-core` §7）。
- **記録の長さと前処理（R 波の検出の誤り）を必ず報告する。** 検出した R 波の区間と、直した後の NN が同じものとは限らない。元の波形・検出した山・直した山・除外した区間を区別して残す。
- **HRV は 3 つに分けて書く。**
  - 時間領域: RMSSD・SDNN・pNN50 など。
  - 周波数領域: LF・HF。**記録が短い（従来の短時間解析では 5 分未満）では、この帯の値は出さない。** 記録の長さと区間の補間のしかた（例 4 Hz）を書く。
  - 非線形: ポアンカレの指数・サンプルエントロピー。
- **LF/HF を「交感・副交感のバランス」の数値として書かない。** LF には複数の影響が混ざり、HF は呼吸に左右される。区間の定義（LFn は LF/TP）と分母を書いてから報告する。
- **スペクトルの解析では、方法（Welch の PSD など）・窓の長さ・重なり・周波数分解能を書く。** 分解能は標本周波数 ÷ 窓の長さで、長い窓ほど分解能は良くなるが平均回数が減ってノイズは増える。零埋めしても分解能は上がらない。窓関数（Hann など）を使う。単位（V²/Hz と dB/Hz の違い）を確かめる。
- 時系列の分類・予測（`aeon`）は §8 の評価の決まりに従う。**分割は時間の順**（未来のデータで過去を予測しない）。
- **生体信号の処理は `$SAI_PROJECT_ROOT/.sai/tools/biosignal/` の道具を使ってよい**（`data-core` §7）。版は `neurokit2==0.2.13`、`pandas<3` に固定する。
- 道具の出力は**診断ではない。** 「この生体信号の指標が疾病を判定する」とは書かない。

出典: K-Dense `neurokit2`（HRV と解析の型）・`aeon`・`physics/spectral-analysis`（スペクトル）

## 8. 機械学習の評価

- **前処理（標準化・補完・特徴の選択）は必ず `Pipeline` の中に入れ、分割のあとに学習させる。** 分割の前に全体へ標準化を掛けると、テストの情報が訓練へ漏れる。**漏洩を防ぐためのいちばん大事な決まりである。**
- **分割の単位を観測の単位に合わせる。**

| データの構造 | 分割 | 理由 |
|---|---|---|
| 同じ人に複数の測定がある | `GroupKFold`（`groups` に人の ID） | 同じ人の測定が訓練と検証の両方に混ざると過大評価になる |
| 時系列 | `TimeSeriesSplit` | 未来の情報を使わない |
| クラスの偏りが大きい | `StratifiedKFold` | fold ごとにクラスの構成を揃える |

- **ハイパーパラメータを選ぶなら入れ子の交差検証**にする（外側の fold で測り、内側だけで選ぶ）。1 つの交差検証で選んで測ると、楽観的な値になる。
- **指標は課題に合わせる。** 分類: ROC AUC・PR AUC（偏りが大きいときは PR の方）・balanced accuracy・較正。回帰: MAE・RMSE・R²。**fold の平均と標準偏差**を出し、`cv` に書く（K8）。**fold の標準偏差は信頼区間ではない**（fold が訓練データを共有するため）。
- **基準と比べる。** 多数派の予測、単純なモデル。数字だけを見せない。
- **SHAP の決まり**（`shap`）:
  - **固定したモデルを、検証済みのデータで説明する。** 説明は予測の検証の代わりではない。
  - 背景データは、訓練または参照する母集団から選ぶ。説明に使う行は保留したデータにする。
  - **何の出力（予測値・確率・対数オッズ・生のマージン）を説明しているか書く。**
  - 加法性を確かめる（`base_values + values.sum(...)` が説明対象の出力と一致するか）。合わなければ、入力の形・前処理・版・出力空間・行の並びを先に確かめる。
  - **SHAP の重要度を因果・公平さ・仕組みの証拠にしない。** モデルがどのように振る舞ったかの説明である。
  - 複数出力のモデルでは、表の図の前に出力（`output_index`）を 1 つ選ぶ。
- **学習に 30 分を超えるなら、自分で動かさず、既存の実験の流れ（`sci-exp-sprout`）を勧める**（`data-core` §11）。

出典: K-Dense `scikit-learn`（Pipeline と評価）・`shap`（SHAP の決まり）

## 9. ベイズ

### 手順

1. **事前分布を決めて理由を書く。** 弱く情報を持つ範囲から始め、その根拠（測定の単位・過去の文献・物理的な限界）を書く。数値を作り出さない。
2. **事前予測の確かめ**（事前分布から作ったデータがありえる範囲か）。「範囲が広い」ことは「情報が無い」ことも「妥当」することも意味しない。
3. **推定する。** PyMC。**独立な chains を 4 本以上**、種を固定。配列の API では定数を自分で足す。
4. **診断する。** 次の基準を**すべて**満たすまで結果は使わない。

   | 診断 | 基準 |
   |---|---|
   | rank R-hat | **1.01 以下**（各推定量について） |
   | ESS（bulk と tail） | **400 以上** |
   | 発散（divergences） | **0** |
   | BFMI（エネルギー） | 問題なし |

   基準を満たさないときは**モデルを直して動かし直す**（サンプルの初期化と幾何を先に直す。回数を増やすのはその後）。検査（K7）が違反を出す。
5. **事後予測の確かめ**（残差の構造・裾・群の効果・時間の依存を見る）。標本内で合うことは外部の検証ではない。
6. **事前分布を変えたときの感度**を見る。幅の広い事前分布・相関のあるパラメータ・分離したロジスティックは、診断が良くても残る。

- **報告するもの**: 事後平均（または中央値）と HDI（**確率を書く。ArviZ の既定が 94% や 89% のことがあるので、`ci_prob=0.95` のように明示する**）・方向の確率。
- ROPE を使うなら**幅と理由**を書く。生の平均差と標準化した d では、同じ閾値を無条件には使えない。**HDI が ROPE に入るかどうか**と「事後の重みが ROPE にある割合」は別の規則である。決める前に決めておく。
- 診断の基準は **§11 の検査 K7 と同じ値**である（1.01・400・0）。
- 版は PEP 723 の欄に固定する（`pymc`・`arviz`）。スナップショットは版によって値が動く。

出典: K-Dense `pymc`（手順と診断）・`statistical-analysis`（ベイズ統計）

## 10. 図の決まり

- 図は `out/fig/` に PNG（300 dpi）で置き、`results.json` の `figures` に `out/` からの相対パスで書く。
- **個々のデータ点か分布を見せる。** 棒グラフだけにしない（平均だけではばらつきと外れ値が見えない）。
- 誤差の棒が何か（SD・SE・95% CI・事後区間）と、**反復の単位が人か試行か**を凡例かキャプションに書く。
- 棒グラフの軸は 0 から始める。点・線図は 0 以外でもよいが、切り詰めたことを示す。**2 本の縦軸は使わない**（必要なときは並べた図にする）。
- 色覚の多様性に配慮した配色（Okabe-Ito の 8 色）を使い、線の太さや形でも区別できるようにする。
- 図を作り変えて結果を強く見せない（軸の範囲・単位・外れ値の有無を変えない）。変換・平滑化・間引きを使ったなら、そのしかたを記す。
- 欠損・除外・ゼロと欠損の区別を図で明示する。区切り値（閾値）を書かない。

出典: K-Dense `scientific-visualization`（誠実なエンコーディング）

## 11. results.json と検査

### 手順

1. `analysis.py` が `out/results.json` を書く。**`plan_sha256` は `plan.json` のバイト列の SHA-256 をスクリプトの中で計算する**（`hashlib.sha256(Path("plan.json").read_bytes()).hexdigest()`）。
2. `check` を動かす。
3. 終了コードが **1** なら違反を直して解析を動かし直す。**直せない違反は `deviation` に理由を書く。** それでも残る違反は解析結果書と report に書く。
4. `table` で表を作る（解析結果書にそのまま貼る）。
5. `log` で MLflow に記録する（`data-core` §8 の決まりに従う）。

| K4 | `test` が計画の `test` と違うときは `deviation` が空でない。計画の `fallback` に替えたときは、`assumptions` に `ok: false` が 1 つ以上ある |

| K9 | `descriptive`: `estimate.value` が有限 |

## 12. 解析結果書と報告の書式

### 解析結果書

- ファイル名 `ana-result-<study>-ID<run_id>.md`、description `解析結果書 <study> ID<run_id>: <結論を 1 文で>`。
- 節は次のとおりで、**この順と名前を変えない**:

| 節 | 中身 |
|---|---|
| `## 結論` | 確証的な仮説ごとに 1〜2 文。効果量と区間を先に述べる |
| `## 結果の表` | `data_result.py table` の出力をそのまま貼る |
| `## 前提の確かめ` | §3 で確かめた前提と、その結論。替えた fallback があれば書く |
| `## 計画からの変更` | `deviation` に書いた点。なければ「なし」 |
| `## 検査の結果` | `check` の終了コードと、残った違反。なければ「なし」 |
| `## 探索的な結果` | 確証的な結果と**はっきり分けて**書く。見出しにも「（探索）」を付ける |
| `## 限界` | 標本の大きさ・測定・交絡・一般化の 4 点 |
| `## 再現の情報` | スクリプトのパス・`plan.json` の sha256・ソフトの版・種・MLflow の run 名 |

### 1 つの結果の書き方（APA の要素）

- **検定名・統計量と自由度・p・効果量と 95% CI・n** を書く。p は正確な値で、0.001 未満は `p < .001`（`p < .05` と書かない）。片側か両側かも書く。
- 例: 「Welch の t 検定で、RMSSD は刺激群が対照群より高かった（t(95.2) = 2.31, p = .023, p_holm = .046, g = 0.47, 95% CI [0.06, 0.87], n = 98、片側）。」
- ベイズの例: 「ベイズの独立標本 t 検定（弱く情報を持つ事前分布，群の平均は正規(0, 10)）で、RMSSD の群差の 95% HDI は [0.4, 7.1] ms で、差が正である事後確率は 99.2% だった。診断は基準を満たした（最大 R-hat 1.003、最小 ESS 1800、発散 0）。」
- 機械学習の例: 「人の ID で GroupKFold（5 分割）した交差検証で、ROC AUC は 0.71（fold の標準偏差 0.05）だった。多数派の予測（0.50）を上回った。」
- 順位の検定のときは U・W・H の統計量と、順位の効果量（順位二列相関など）を書く。中央値・四分位範囲も書く。

### research-tree への置き方

- 数字を含む F には `cites`（論文）か `report`（**解析結果書の waggle トークン**）のどちらかが要る。データ分析は木に F を足さない（`data-core`）。
- 木には E だけを足す（`add_e`）。F は足さない。結論は解析結果書（REPORT）と MLflow に書く。
- 探索的な結果（計画外）は**文の頭に「（探索）」**と書く。

```text
{"op":"add_e","parent":"E12","text":"H1 RMSSD の群差（Welch の t）","mlflow":"ID131-test"}
```

- report は最後に 1 つだけ保存する。**数字があれば解析結果書のトークンを書く。** 探索的なら冒頭に「（探索）」を付ける。書き方は `sci-core` の「## 出力」。

出典: K-Dense `statistical-analysis`（報告の書式）

## 13. 統計の誠実さ

- **最も悪い失敗は、計算の誤りではなく、黙って解析を変えることと、都合のよい結果だけを報告することである。**

### 決まり

- **計画した検定はすべて報告する。** 有意でなくても、計画どおりに実行したものは全部書く。
- **計画からの変更はすべて `deviation` に書く。** 変えた結果が探索的なら、そうラベルする。
- **p 値の閾値の前後で言い方を変えない。** p = .049 と p = .051 で「傾向があった」と言わない。閾値の前後で同じ言葉を使う。
- **片側の検定は、向きのある問いを事前に決めたときだけ。** 結果を見てから片側にしない。
- **相関から因果を言わない。** 交絡を調整したからと言って因果とは言えない（§6）。
- **統計的に有意と、実質的に意味があるを分ける。** 大きな標本では意味の無い効果が p < .001 になる。解釈は効果量から書く。
- **データを見てから外れ値を消さない。** 消すのは計画に書いた規則があるときだけ。消したときと消さないときの両方を見る。
- **同じデータを、仮説を作って確かめるために使わない。** 結果を見てから仮説を立てると p 値は楽観的に偏る。確証的な解析は結果をみる前に計画へ書いておく（§1）。

### よくある落とし穴

| 落とし穴 | 何が起きるか | 避け方 |
|---|---|---|
| 擬似反復 | 同じ人の測定を独立な反復として数える | 反復の単位を人にする（§2） |
| 多重比較を補正しない | 20 個の独立な検定で、少なくとも 1 つが約 64% の確率で誤って有意になる | family を決めて補正する（§4） |
