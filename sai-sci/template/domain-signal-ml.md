# 分野の観点: 信号処理・機械学習（signal-ml）

## 問いを整理するときの枠
- データセット: 被験者は何人か、記録条件・機器・サンプリング周波数は何か、ラベルを誰がどう付けたか。
- 前処理: フィルタ、正規化、リサンプリング、アーティファクトと欠損の扱いを決める。
- 特徴量 / モデル: 入力の形（チャネル数・窓長など）、モデルの種類、学習の手順を決める。
- 評価の分け方: 被験者をまたぐか、時間で分けるか、ランダムに分けるか。交差検証の単位は何か。
- 指標: 何を主指標にするか。クラスの偏りを踏まえた指標（例: balanced accuracy、F1、AUC）を選ぶ。
- 比較相手: 単純なベースラインと、同じデータ分割・同じ前処理での既存手法。
- 対象とするタスクを 1 つに絞る（分類か回帰か、検出か予測か）。
- 主張したい範囲を決める（同じ条件のデータに限るのか、別の被験者・別の装置まで広げるのか）。

## 証拠の強さの見方
- 公開データセットで再現できるか、コードとデータ（またはその入手手順）が公開されているか。
- 独立した外部データでの検証があるか。同一データ内の分割だけでは弱い。
- 検証の深さ: 発見のみ < データ内の分割検証 < 外部データでの検証 < 独立した追試 < 実運用に近い評価。
- 比較が公平か: 同じデータ分割、同じ前処理、同じ指標で比べているか。
- ハイパーパラメータの探索とモデル選択を、テストデータではなく学習・検証データだけで行っているか。
- 統計的な検定・信頼区間・複数シードでのばらつき（平均だけでなく標準偏差）が示されているか。
- モデルと実験の報告が十分か（データ、分割、前処理、探索範囲、乱数シード）。
- 結論がデータの範囲を超えていないか（単一データセットの結果を一般化していないか）。

## よくある落とし穴
- 被験者内の分割による情報の漏れ: 同じ被験者のデータが学習とテストの両方に入る。
- 前処理や特徴量の作り方をテストデータ全体に当ててしまうリーク（正規化、特徴選択、次元圧縮など）。
- クラスの偏り（不均衡）を無視した Accuracy の報告。
- 前処理や評価条件の違いによる比較不能（他論文の数値をそのまま並べる）。
- 単一データセットだけの評価を、そのまま一般化する。
- テストデータでのハイパーパラメータ調整。
- 乱数シード 1 回だけの結果を報告し、ばらつきを確かめない。
- 最先端（SOTA）の数値だけを見て、実験条件の違いを確認しない。
