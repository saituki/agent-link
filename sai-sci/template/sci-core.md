# research-tree で動くエージェントの共通の決まり（sci-core）

このファイルは `sai-sci init` が研究プロジェクトに配った最初の版です。ユーザーが自由に直せます。

## context の読み方
最初のメッセージの「# context」は、起動の直前に research-tree から切り出して作り直したものです。「# task_text」（依頼文。目的・NODE・期待する成果）と重ねて読んでください。

- `## PROJECT`: 対象が木の全体（`--node` なし）のとき、研究の型と対象。
- `## TREE`: research-tree のうち、この回で見る部分。node agent は対象とその下、manage agent は軸の Q から対象までの祖先と対象とその下（対象が木の全体なら全部）。support agent には出ません。対象の行の末尾に `← TARGET` があり、次の行の `>` が対象の本文です。
  - 軸（Q）の行の `[A n・深さ d]` は、その軸の直下の生きた A の数（`n`）と、段（`d`。軸は 1）です。A の行の `[A n・F m]` は、その A の直下の A の数と F の数です。直下の A（`n`）が 7 を超えると `TOO_FLAT` が出ます（`lab-review` を勧める信号）。A の行の `[条件]` は、`rel` が `condition` の A です。
  - S の行の `[固定: … / 新規: … / 未回答: n / 実験: E n 件]` は、その S の回答の区分と未回答の問いの数です（「seed の問いと回答」の節）。空の区分は出ません。
- `## STUDY_SEED`: 対象が S のとき、その S の親の seed（D）の題・本文と、問いの表（問い・軸・seed の回答・この S の回答）。研究の制約なので、必ず読む。
- `## GUIDE`: 対象（か一番近い祖先）の Q の GUIDE（Extract・Child Q など）。
- `## SEARCH_HISTORY`: TREE の Node の検索の記録（find（Library）と search（外部）の両方）。同じ検索を繰り返さないために読む。
- `## ALLOWED_OPS`: このブロックが出せる OP と、その項目。
- `## PAPER_OUTLINE`: 読む論文の節の一覧（あるときだけ）。
- `## TARGET_PAPERS`: blind_first のときだけ、research-tree の代わりに出る対象の論文。

## research-tree
research-tree は、seed・root・sprout の 3 つの役に分けてできています。層は次のとおりです。

```
E（BRANCH）── S か E の下。実験の 1 回
 │
S（SPROUT）── 1 研究＝研究計画。親は D。D の未回答の問いに回答していく。全部答えると完成
 │
D（seed）──── 1 研究の制約。問い（SQ）と回答（SA）の表。親なし。複数。S の親として並ぶ
 │
Q（軸）── 親なし。task・target・data・method・output・metric の 6 つ
├ A（大分類。抽象的な種類）
│ ├ F（論文の事実。stance は support・deny・issue）
│ └ A（subtype。親の一種）
│   ├ A（具体的な種類）
│   │ └ A（condition。親の属性・条件）…
│   └ A …
└ A（大分類）…
```

- **root** は分野の可能性の幅です。seed に縛られません。軸（Q）は軸ごとに 1 つずつ並びます。木は「軸（Q）→ A → A …」の形です。A の下に A と F を置きます。軸以外の Q は作れません（旧形式のプロジェクトには、A の下の Q が残ることがあります）。
- root の Q・A に「この研究では」「本研究では」を書きません。研究の決定は seed（D）と sprout（S）に書きます。

#### 木の形と抽象度（方針）
- 軸（Q）の下には、最も抽象的な種類（大分類）の A を置きます。具体的な種類は、その A の下の A（`rel` は `subtype`）に置きます。
- 同じ親の直下の子は、同じ分け方・同じ詳しさにそろえます。分け方が分かるように、親の A の本文に「分け方の基準: …」を 1 行書きます。
- 直下の A が 7 件を超えたら、見直す目安にします（強制ではありません）。
- 兄弟の詳しさがずれていると分かったら、親の A を `add_a` で足し、兄弟を `move_node` で移して整えます。ID・F・子はそのまま保たれます。迷うなら足さず、報告に書きます。
- `condition`（`rel`）は、種類を細かく分ける子ではなく、親の属性や条件を表す子です。★ を付けた A か、seed の回答（固定）に当たる A の下だけに置けます。
- 木の深さは、目安で 4 段までです。
- **seed（D）** は 1 つの研究の問いの一覧です。問い（`SQ<n>`）に、テキストか root の path（A）で回答します。
- **sprout（S）** は 1 研究＝研究計画です。1 つの seed（D）の未回答の問いに回答していく計画で、親は D です。全部の問いに回答すると完成し、実験（E）を足せます。1 つの D から複数の S を作れます。
- 研究の決まりは D と S に書きます。root の A に書きません。先行研究を論文から復元した研究と自分の研究は区別しません（どちらも D と S）。

#### seed・root・sprout の考え（利用者の考え）
1. seed の問いを考えるのは利用者の仕事です。
2. 研究開始時点で回答が分かっている問いもあります（初期制約）。それは seed の回答として書きます。
3. seed の未回答の問いに回答すると、実験を始められます。未回答の問いに root の path を割り当てて sprout を完成させる、というのがこのことです。
4. root の役割は、seed の問いの答えの選択肢を増やすことです。root は seed に縛られません。
5. agent の役割は、seed の問いに合う選択肢を root から探すことです。
6. 「同型の手法はあるか」を探す作業は、seed の未決定の問い（例:「どの手法を使うか」）の回答候補を増やすために、root に node を足す作業です。
- E（BRANCH）は S か E の下に作る実験の 1 回です。E の下に F は置きません。実験の結論は REPORT と MLflow に書きます。
- A は選択肢 1 つの答えです。A に出典（`#番号`）は書けません（op が断る）。選択肢の根拠は、その A の下の F に書きます。F の無い A は Next Action の NO_FINDING に出ます。
- F は論文の事実で、A の下に付きます。stance（`support`・`deny`・`issue`）を必ず持ちます。
- ★ は目印で、どの種類の Node にも付けられます。道や進み具合を決めません。付けるのは利用者だけです。

### seed の問いと回答
seed（D）は問いの一覧です。本文（body）は背景と制約の自由な文です。
- **問い**（`SQ<n>`）: 研究の問い 1 つ。`add_seed` で雛形の 7 問が入ります。

| 問い | 軸（axis） |
|---|---|
| 解く問題は何か | `task` |
| 対象は誰・何か | `target` |
| どのデータを使うか | `data` |
| どの手法を使うか | `method` |
| 何を出力するか | `output` |
| どの指標で評価するか | `metric` |
| 成功基準は何か（指標の値と向き） | 無し |

  - 前の 6 問には軸が付き、成功基準には付きません。
  - 問いは利用者が足す・直す・消します。agent は `add_seed_q`・`edit_seed_q`・`remove_seed_q` に承認が要ります。
- **回答**（`SA<n>`）: 問い 1 つに、テキストか root の path（A）で回答します。1 つの問いに複数の回答を付けてよいです。
  - seed の回答 ＝ **固定**（初期制約。その seed の全部の sprout に効きます）。
  - sprout の回答 ＝ **新規**（その sprout で決めたこと）。
- 「範囲」「新規性」「記載なし」という状態はありません。言い換えは次のとおりです。
  - 範囲 → 問いを具体的にする（例:「どの手法を使うか（範囲: Costa 型。A94 の下から選ぶ）」）か、問いを足す。
  - 新規性 → seed では未回答のまま残し、sprout で回答する。
  - 記載なし → seed にテキストで「記載なし: <理由>」と回答する。

```
seed（D1）「発作部位の特定」
  SQ1 解く問題は何か（task）      → 固定: テキスト「発作部位の特定」
  SQ2 対象は誰・何か（target）     → 固定: A12（側頭葉てんかん患者）
  SQ3 どのデータを使うか（data）   → 固定: A30（術前の EEG・ECoG）
  SQ4 どの手法を使うか（method）   → 未回答
  SQ5 何を出力するか（output）     → 未回答
  SQ6 どの指標で評価するか（metric）→ 未回答
  SQ7 成功基準は何か              → 未回答
sprout（S10）「発作起始の推定」     → 新規: SQ4 A94、SQ7 テキスト「AUC 0.8 以上」
```

#### sprout（S）の完成と凍結
- S は、1 つの seed の未回答の問いに回答していきます。答える問いの全部に D か S の回答が 1 つ以上あると、**完成**（`complete: true`）です。完成するまでは `missing`（未回答の問い）が出ます。
- 完成した S は**凍結**します。完成した時点の問いの一覧を保ちます。後から seed に問いを足しても、完成した S には効きません（未完成の S には効きます）。
- 完成していない S には実験（E）を足せません（`add_e` は断られます）。

### sprout（S）の回答の区分
- 区分の札は「固定」（seed の回答）と「新規」（sprout の回答）の 2 つです。
- `sai-sci node <S>` は、この区分を次の順に出します: seed（固定）→ 新規（sprout の回答）→ 未回答 → 実験（E）→ 本文。
- `sai-sci compare S1 S2 …`（2〜10 個）は、S を行、軸の付いた問いを列にした表で比べます。欄は、その問いの回答です。Web の比べる画面は `#/research/compare?s=S1,S2` で開き、同じ JSON を使います。

## 抽象度をそろえる
A を足す前に、同じ親の直下の A と比べて、次の 3 つのどれかを決めます。
1. 同位: 同じ基準・同じ詳しさ → その親に足す（`add_a` の `parent` に親の ID）。
2. 下位: どれかの A の一種 → その A の下に足す（`parent` にその A の ID）。
3. 上位、または兄弟が詳しすぎる → 親の A を `add_a` で足し、詳しい兄弟を `move_node` でその下へ移す。

どれも決められないときは、報告に書いて足しません。直下の A が 7 件を超えたら 2 と 3 を考えます。Next Action に `TOO_FLAT` が出たら、block `lab-review` で木を見直します。

## 起動者と質問
- あなたを起こしたのは、CARD の起動者です。`echo "${SAI_IS_SUBTASK:-0}"` が `1` なら子（`task create` で起こされた。報告は親へ返す）、`0` なら root（Card で起こされた。起こしたのは Human か、Human の代わりの Professor）です。
- 確かめ・質問は、**必ず質問ツール**（`AskUserQuestion`）で聞きます。返答の本文だけで尋ねて止まってはいけません。質問は Web の画面にも出るので、利用者も見ています。先に答えた方が採られます。root の質問には、起こした Human か Professor が Web（`sai-web answer`）で答えます。
- 質問の文・選択肢・報告に、鍵・合言葉の値を書きません。値が要るときは環境変数の名前だけを書きます。

## 最初にすること
1. この回の行動の目的を、1 文で言い直して示します。
2. 依頼文の NODE（`Q12` などの ID と文）を先頭に書きます。Node が無いときは推測で選びません。作業を始めず、質問ツールで起動者に「どの Node のための行動か」を確かめて止まります。
3. `# context` の節が「（…範囲を作れませんでした…）」の 1 行だけだったときは、`sai-sci context --run "$SAI_PARENT_RUN_ID"` で取り寄せてから始めます。それでも取れなければ、質問ツールで起動者に伝えて止まります。
4. research-tree がまだ無いときは、起動者に Web の「始める」か `sai-sci init --type <型>` の実行を頼みます。自分では打ちません。

## 確かめの地点
次の 2 か所で止まり、質問ツールで「この方向で進めてよいか」を起動者に聞いてください。
1. 目的を言い直したとき
2. 木を変える op を出す前

依頼文に `確認: 少なめ` とあれば 2 の前だけで止まってください。`確認: 多め` とあれば 1・2 に加えて「3. 検索を始める前（検索語の一覧を見せる）」でも止まってください。依頼文に書いていなければこの既定（1・2）に従ってください。

## 範囲を守る
- TREE と依頼文の NODE と OUT_OF_SCOPE がこの回で扱う範囲です。範囲の外の話を良いからと広げません。
- 範囲の外で気づいたことは、report の「## OUT_OF_SCOPE」に書いて議論しません。利用者が見たうえで、次の CARD に活かします。

## research-tree を変える（op）
research-tree・`mind.md`・`state.md`・`tree.md` を直接書き換えてはいけません。木への変更はすべて `sai-sci op` で出します。

出し方は、次の形をそのまま打ちます。

```bash
sai-sci op <<'EOF'
{"ops":[
  {"op":"add_a","parent":"Q3","text":"側頭葉てんかん"},
  {"op":"add_a","parent":"Q3","text":"発達性てんかん性脳症"}
]}
EOF
```

**op の規則（ここにまとめます。block には書き写しません）**
- 1 回の `op` は 20 件まで。21 件以上は、分けて 2 回に出します（`ops は 1〜20 件です`）。
- `add_f` の `text` は 1〜3 文です。文の区切りは「。」「？」「！」と、後ろが空白か行末の「.」「?」です。4 文以上は、文を分けて別の F にします（`text は 3 文までです`）。
- ID の形は `Q12`・`A5`・`F3`・`E2`・`S1`・`D1` です。数だけ（`12`）は書きません。
- 木の全体を指すときは `--node` を省きます。木の根の ID はありません。
- 1 件でも違反があれば、何も書かれません。エラーは `<n> 件目（<op>）: <理由>` の 1 行で返るので、その件を直して出し直します。
- 段を重ねるとき（新しい A の下に A を出すなど）は、段ごとに分けて出します。返った ID（`result`）を次の段で使います。
- **出せる op とその項目（必須・任意）は、`# context` の `## ALLOWED_OPS` を見てください。** ALLOWED_OPS に無い op は出せません。

**主な op の形**
| op | 許可 | 形（例） | 結果 |
|---|---|---|---|
| `add_a` | 要らない | `{"op":"add_a","parent":"Q3","text":"側頭葉てんかん"}` | `A<n>`（`rel` を省くと `subtype`。`"rel":"condition"` は ★ の A か seed の回答の A の下だけ） |
| `add_f` | 要らない | `{"op":"add_f","parent":"A10","text":"#12 は、側頭葉てんかんの発作起始を述べる。","stance":"support","cites":["#12.3.2"]}` | `F<n>` |
| `move_node` | 要らない | `{"op":"move_node","node":"A12","to":"A30"}` | `A12`（ID は変わらない。F・子ごと移る。移し先は A か Q） |
| `add_sprout` | 要らない | `{"op":"add_sprout","seed":"D17","title":"発作起始の推定","answers":[{"q":"SQ4","a":"A16"}]}` | `S<n>`（`range` も返る） |
| `add_answer` | 要らない | `{"op":"add_answer","to":"S3","q":"SQ4","a":"A94"}` | `SA<n>` |

**seed・sprout の op の形**（問い `SQ<n>`・回答 `SA<n>`。`to` は D か S）
```json
{"op":"add_seed","title":"発作部位の特定","body":"## 背景\n…"}
{"op":"add_seed_q","seed":"D1","text":"どの指標で発作の検出を評価するか","axis":"metric"}
{"op":"edit_seed_q","q":"SQ4","text":"どの手法を使うか（範囲: Costa 型。A94 の下から選ぶ）"}
{"op":"remove_seed_q","q":"SQ7"}
{"op":"add_answer","to":"S3","q":"SQ4","a":"A94"}
{"op":"add_answer","to":"D1","q":"SQ1","text":"発作部位の特定"}
{"op":"edit_answer","answer":"SA5","text":"AUC 0.85 以上"}
{"op":"remove_answer","answer":"SA5"}
{"op":"add_sprout","seed":"D1","title":"発作起始の推定","answers":[{"q":"SQ4","a":"A94"},{"q":"SQ7","text":"AUC 0.8 以上"}]}
```
- `add_seed`・`add_answer`・`edit_answer`・`add_sprout` は許可が要りません。`add_seed_q`・`edit_seed_q`・`remove_seed_q`・`remove_answer` は許可が要ります。
- `add_answer` は、S から、seed で回答済みの問いには答えられません。完成（凍結）した S の対象外の問いにも答えられません。同じ A を同じ問いに 2 回は書けません。
- `add_sprout` の `paths` は断られます（廃止）。`answers` を使います。
- 未完成の S への `add_e` は断られます（「S2 は未完成です（未回答: SQ3, SQ5）…」）。

- `add_a` の `parent` は A か Q（軸）です。`rel` は `subtype`（省略）か `condition` です。
- `move_node` は、A を別の A か Q（軸）の下へ移します。移す先が移す A 自身か、その子孫のときは断られます。許可は要りません。
- `add_sprout` の `answers` は、`{"q":"SQ3","a":"A12"}` か `{"q":"SQ5","text":"…"}` の配列です（0〜40 件）。同じ問いに複数の回答を付けてよいです。
- `add_f` の親は A だけです。`stance` が要ります。E の下に F を置きません。数字を含む文には、出典（`cites`）か REPORT のトークン（`report`）が要ります（「根拠」）。
- `add_seed`（許可は要らない。seed を作る前に質問ツールで内容を確かめる。先頭の選択肢は `作る`）: 項目は `title`（必須・1〜120 字）と `body`（任意・0〜2000 字。上の「seed の問いと回答」）。結果は `D<n>` です。雛形の 7 問が入ります。
- ★・文の直し（`edit`。D の文の直しを含む）・星（`star`・`unstar`）は利用者だけの操作です。出せません。

## 許可を取る
許可が要る op（`copy`・`remove`・`add_seed_q`・`edit_seed_q`・`remove_seed_q`・`remove_answer`）を出すときは、質問ツールで次の決まりに従って聞きます。`add_a`・`add_f`・`move_node` は許可が要りません。

- 1 回の質問に 1 問だけです。
- 先頭の選択肢を `許可する`、2 つ目を `許可しない` にします。
- 質問文に、これから行う op の一覧（op 名と対象の ID・文）を書きます。
- `許可する` が選ばれなかったら、その op は出しません。
- `sai-sci approval record` は自分で呼びません。質問の答えは、フックが記録します。
- 許可 1 件は、許可が要る op を含む `op` の 1 回で使われます。使い切ったら、次の許可を取り直します。

## 根拠
- 出典は `literature-hard-rules` に従います。文献を推測で書かない。API の返り値に無い PMID・DOI・題名・著者・年・誌は書いてはいけません。
- F の文で、論文が自分の研究を「本研究では」と書いていても、F には「#12 は…」のように論文を主語にして書きます（「本研究」は読む人の研究と取り違えられるため）。
- F の `cites` は次の形です: `#37`・`#37 §3.2`・`#37.5`・`#37.5.2`・`#37.5.2-4`・`#37 Fig.3`。
- 数字（0〜9）を含む F には、出典（`cites`）か、自分の REPORT（実験の判定書・データ表・解析結果書など）の waggle トークン（`report`）が要ります。論文の値を書くときは `cites`、自分で出した結果を書くときは `report` を付けます。
- **`cites` と報告の引用に書けるのは、この run で CLI（`sai-paper`・`sai-sci`・`sai-link doc read`）が出力した番号だけです。** 見ていない番号は、記憶や推測で書かず、先に `sai-paper` で読んでから引きます。見た番号は台帳（`.sai/seen_ids/<run_id>`。MLflow とは別の物）に残っていて、無い番号は `台帳に無い番号です: #37.5.2` で終了コード 2 になります（何も書かれません）。節・塊（`#37.5`・`#37.5.2`）は読んだとおりの番号を書きます。論文（`#37`）は、その論文のどれかの番号を見ていれば通ります。
- `cites` の論文が Library に無いと弾かれます。Library に無い論文は、`sai-sci search` で見つけた候補を利用者に取り込んでもらってから出します（search は Library に入れません）。
- 根拠が足りないときは「Library の資料では答えられない」と書き、`[GAP: 推奨検索: <英語の検索語>]` を残します。

## 迎合しない
- 対象の A に不利な F（限界・失敗する条件・再現できなかった報告）を、少なくとも 1 つ探します。向きを示す項目は無いので、F の文で「何に反するか」を書きます。
- 探したが見つからなかったときは「探したが見つからなかった」と report に書きます。支持の報告だけにしません。
- 事実（論文に書いてあること）と解釈（あなたの考え）を分けて書きます。

## コマンド
`sai-sci` のコマンド（`sai-sci status` / `sai-sci find` / `sai-sci report content` など）は、そのまま打ちます。

`sai-sci` が `command not found` になったら、自分でフルパスを探さずに、質問ツールで起動者に「`sai-sci` に PATH を通してください（README の「起動」）」と伝えて止まってください。

論文の中の語を探すときは、`extract.md` を `grep` しません（1 行が数 MB になり、出力が読めなくなります）。次の 2 つを使います。
- `sai-paper find "<語>" --paper <ID>`: 論文 1 本の中で語を探す（`<ID>` は Library の番号）。
- `sai-paper content read <ID>.<節>`: 節・塊を読む（例 `sai-paper content read 37.5`・`sai-paper content read 37.5.2`）。節の一覧は `sai-paper content outline <ID>`。

## 出力
node agent・manage agent は report を `sai-link doc write` で 1 つだけ保存します（途中のメモは保存しません）。support agent は report を保存せず、呼んだ agent に `sai-link task report` で答えを返します（下の「## 終わり方」）。

本文は標準入力で渡し、次の形で打ちます。

```bash
sai-link doc write --filename <ブロックID>-<英字>.md --description "<ブロックの名前>: <1 文>" <<'EOF'
（本文）
EOF
```

- `--filename` は `<ブロックID>-<内容を表す短い英字>.md`（例 `lab-read-onset-accuracy.md`）。
- `--description` は「<ブロックの名前>: <内容を 1 文で>」。1 行・200 字までです。
- **frontmatter は書きません。** 道具が付けます。
- 保存のとき、道具が `sai-sci report prepare` で検査します。違反ならエラー文が返り、保存されません。直して保存し直します。
- そのブロックの「## 出力の形」の見出しを、すべて書きます。
- 論文を引用するときは `[#37]` の形で書きます。Library に無い番号は弾かれます。
- 末尾に次の 2 つの節を書きます。名前は変えません（次の CARD が読みます）。書くことが無い節は「なし」と書きます。**「## 引き継ぎ」は書きません**（道具が弾きます）。

```markdown
## 木への変更
| 結果 | op | 中身 |
|---|---|---|
| F31 | add_f | 頭皮脳波の発作起始の推定は… |
| A41 | add_a | 発作の予兆の検出 |
| 未実行 | remove | 重複の A の削除（許可が無かった） |

## OUT_OF_SCOPE
<範囲の外で気づいたこと。無ければ「なし」>
```

- 「結果」は `sai-sci op` が返した ID（`result`）です。出せなかったものは「未実行」と書き、理由を添えます。

## 終わり方（LabAgent の種類ごと）
あなたのブロックが node agent・manage agent・support agent のどれかは、ブロックの本文の最初に書いてあります。

- **node agent・manage agent**: REPORT を `sai-link doc write` で 1 つ保存してから終えます（上の「## 出力」）。正常に終わったかどうかは、REPORT があるかで見られます。
- **support agent**（子として呼ばれたとき）: REPORT は保存しません。呼んだ agent に `sai-link task report` で答えを返して終えます。

report を保存したら、次のどちらかで終えます。終えたあとにこの run は何もしません。

- **子の run（`SAI_IS_SUBTASK` が `1`）**: `sai-link task report` を呼びます。report には 3〜10 行で、結論・保存した report のトークン・`sai-sci op` で出した ID・残った問いを書きます。
- **root の run（`SAI_IS_SUBTASK` が `0` あるいは無い）**: 要点を伝え、質問ツールで「完了してよいか」を起動者に確かめます。了承されたら、`sai-link run finalize` を `report`（上と同じ要点）付きで呼びます。直しを求められたら、直して保存し直してから、もう一度確かめます。
- 例外: 実験の連鎖（`sci-exp-branch`・`sci-exp-review`）は、確かめずに `sai-link run finalize` で終えます（ブロックの本文のとおり）。

`sai-link run finalize` は、次の形で打ちます（`--report` の文は要点 1 文）。run_id は省くと自分の run になります。

```bash
sai-link run finalize --report "<要点>"
```
