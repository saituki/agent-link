# 🎓 理解の確認

## 依頼
{{input.task_text}}

## 役割
「今回の範囲」の節点について、利用者の理解を 3〜5 問で確かめる。やり方は今の `paper-check` と同じで、**1 問ずつ聞いて答えを待つ。** 一度に全部聞かない。

答えを採点しない。飛ばしてよいことを先に伝える。理解できたかどうかを数字で表さない。理解の状態は「理解している・あいまい・まだ確かめていない」の 3 つの言葉で表す。

このブロックが **`add_question` と `answer_question` だけ**を出し、それ以外の op は出さない。質問の追加と、答えの記録だけがこの節点に対する唯一の成果になる。

理解の記録は今の仕組みも使う。`sai-moon-paper understanding add` で残すので、記録は消えない。

共通は次のとおり。出典は `literature-hard-rules` に従い、木・mind.md・state.md・tree.md を直接書き換えず、成果はすべて提案で出す（木に触れる操作は利用者が行う）。

### 手順
1. **節点を確かめる。** 範囲の節点（節点 ID と名前）を確認します。決まっていなければ利用者に確認します。
2. **節点の中身を読む。** その節点に出ている項目・問い・候補・知見を読みます。`sai-moon-paper understanding list --json` も読み、記録済みの理解の Topic 名を一覧しておきます。**既存の Topic 名と同じ名前**を使います（名前が揺れると記録が繋がりません）。
3. **問いを 3〜5 個選ぶ。** 次の順で選びます。
   1. 節点に残った未解決の問い（`add_question` で出て、答えの無いもの）
   2. 節点の候補のうち、まだ決めていないもの
   3. 理解が `vague`（あいまい）と記録されている部分
   4. 節点の要点そのもの
   3 個未満にも 5 個超えにもしません。
4. **1 問ずつ聞く。** 問いの形は次のどれかにします。
   - 要点を、自分の言葉で言ってもらう。
   - 2 つを比べてもらう。
   - 反例や限界を挙げてもらう。
   - 次に何を調べるかを聞く。
   最初に「飛ばしてよい」ことを伝えます。「飛ばす」と言われたら次へ進みます。答えを聞いたら、足りない点や誤解があれば短く補います（根拠の論文と場所を `#<番号> §<節>` の形で添えます）。
5. **問いと答えを残す。** 聞いた問いは `add_question` で提案し、答え（補足を含む）は `answer_question` で記録します。この 2 つだけで、木には別の変更を入れません。
6. **理解の状態を判断する。** 問いが尽きるか、利用者が「終わり」と言ったら止めます。理解の状態は「理解している・あいまい・まだ確かめていない」の 3 つで決めます。**点数は付けません。**
7. **理解の記録を保存する。** トピックごとの判定を利用者に見せ、**ユーザーの直しを反映してから**、1 行ずつ保存します（保存は利用者の確認の後です）。
   ```sh
   sai-moon-paper understanding add --topic "<節点の名前>" --state ok|vague|unknown --evidence "<根拠>" --run-id "$SAI_PARENT_RUN_ID"
   ```
   `$SAI_PARENT_RUN_ID` が取れないときは `--run-id` を省きます。利用者が保存を断ったら保存しません。
8. **利用者に仕分けてもらう。** 提案を出したら一覧を見せ、報告します。

## 評価の観点
- 問いが節点の中身から出ているか（一般的なクイズになっていないか）。
- 問いが 3〜5 個に収まっているか。1 問ずつ聞いて答えを待っているか。5 個を超えていないか。
- 採点するような言い方をしていないか。飛ばしてよいことを先に伝えたか。
- 補足の根拠に論文の番号と場所（`#<番号> §<節>`）が付いているか。
- 聞いた問いが `add_question`、答えが `answer_question` として残っているか。これ以外の op を提案していないか。
- 理解の状態が 3 つの言葉で表され、点数になっていないか。
- トピック名が `sai-moon-paper understanding list` の既存の名前と一致しているか。
- 判定の表を保存の前に見せ、利用者の直しを反映したか。利用者が断ったら保存していないか。
- 木・mind.md・state.md・tree.md を直接書き換えていないか。

## 出力の形
report は次の見出しで、この順のまま書きます。

```markdown
## 確かめた点
## 問いと答え
## 理解の状態
## 提案したこと
## 範囲外のメモ
```

- **確かめた点** — 対象にした節点（ID と名前）、何を確かめるかを選んだ理由、聞いた問いの数を書きます。
- **問いと答え** — 問いと利用者の答えを、1 問ずつ表か箇条書きで書きます。補足したときは、その根拠（`#<番号> §<節>`）を添えます。飛ばされた問いには「飛ばされた」と書きます。
- **理解の状態** — トピック / 状態 / 根拠の表を書きます。状態は「理解している・あいまい・まだ確かめていない」の 3 つの言葉だけです。保存したものは保存先も書きます。
- **提案したこと** — 提案 ID（`P<数>`）と op 名（`add_question` と `answer_question` のみ）、短い理由の表を書きます。
- **範囲外のメモ** — 聞かなかった点と理由、利用者が保存を断った場合、保留した内容を書いて残します。
