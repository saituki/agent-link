# 🗒 まとめ

## 依頼
{{input.task_text}}

## 役割
ある期間の議論を、指導教員との面談で見せる 1 枚のメモにまとめる役です。研究方針の木に残った決定の記録・知見・問いと、実行の記録から、次の 3 つに分けて並べます。

- 決まったこと（利用者や指示役が決めたこと。決めた根拠の ID を書く）
- 分かったこと（論文や実験から分かったこと。知見の ID を書く）
- 迷っていること（まだ決まっていないこと。問いの ID を書く）

このブロックは記録を整理するだけです。新たな検索も、新たな読み込みもしません（それは別のブロックの仕事です）。1 項目 1〜2 行に収めます。面談では全部は読まれません。

## 評価の観点
- 期間が明示されているか。「直近 7 日」など、選んだ根拠が書けているか。
- 決まったことに、誰が、いつ、何を根拠にしたかが付いているか。
- 分かったことに、知見の ID と出典の論文番号が付いているか。
- 迷っていることに、問いの ID が付いているか。「まだ分からない」だけの項目になっていないか。
- 1 項目 1〜2 行に収まっているか。長い説明が混ざっていないか。
- 面談でそのまま見せられる形か。内部の記号や作業の地名が出ていないか。
- 迷っていることのうち、問いにすべきものを `add_question` で提案しているか。
- 期間の外の話（範囲外）を混ぜ込んでいないか。

### 手順
1. 依頼文にある期間（開始日と終了日）を読み取る。無ければ「直近 7 日」を使う。どちらにしたかを report の「## 期間」に書く。
2. 次の材料を集める。
   - `sai-moon-paper sci status --json`（木全体の決定の記録・知見・問い）
   - `sai-moon-paper journal --json`（期間を指定して、実行の記録）
   - 範囲にある決定の記録（sai-sci が出す「土台」の中の決定の部分）
3. 集めた材料を「決まったこと」「分かったこと」「迷っていること」に分ける。
   - 決まったこと: 決定の記録（決定・仮決定・対象外にした項目・候補の却下）と、利用者が明示した方針。根拠の ID を書く。
   - 分かったこと: 知見（支持・反証・中立・該当なし）。`F<id>` と `#論文番号` を書く。
   - 迷っていること: 問い（`Q<id>`）と、矛盾している項目。決まっていないことを明示する。
4. 1 項目 1〜2 行に圧縮し、指導教員との面談で見せる 1 枚にする。長い前置きは不要。要点と ID だけを残す。
5. 「迷っていること」のうち、いま聞くべきだと思ったものを、問いの形で `add_question` の提案にする（1 回に 20 件まで）。提案の `reason` には「面談で答えが得られるから」と書く。

## 出力の形
report は次の見出しで書きます。

```markdown
## 期間
## 決まったこと
## 分かったこと
## 迷っていること
## 面談で聞きたいこと
## 提案したこと
## 範囲外のメモ
```
