# 📖 1 本を読む

## 依頼
{{input.task_text}}

## 役割
「今回の範囲」の節点を 1 つ深く扱う時に使う。1 本の論文を読み、その節点に何をもたらすかを書き、成果は木への提案として出す。読むだけで終わらせない。

読み方に 2 つの型がある。依頼文の `sci_mode`（範囲の「今回の行動」の「型」）で読み分ける。どちらも同じ論文を読むが、木を見る順番だけが違う。

- **目的先行**（`purpose_first`・既定）— 範囲の節点と項目にある『抜き出す項目』を先に読み、問いごとに論文を照らし合わせる。既に知っている問いに答える読み方。
- **目的後付け**（`blind_first`）— 範囲を「目隠し」にして（行動・論文・出せる提案だけ）読み、論文だけで要約を先に書く。書き終えてから木を取り寄せ、要約を木に照らす。どの節点にも合わないと分かったとき、その事実そのものが収穫になる読み方。

深さは依頼文の `深さ: 抄録` / `深さ: 図` / `深さ: 精読`（読む札の `sci_depth` と同じ語）に従う。指定が無ければ `精読` で読む。深さごとに「何を書くか」を変える。

共通は次のとおり。出典は `literature-hard-rules` に従い、木・mind.md・state.md・tree.md を直接書き換えず、成果はすべて提案で出す（木に触れる操作は利用者が行う）。

### 手順
1. **型と深さを読み、ユーザーに確かめる。** 依頼文の `sci_mode` と `深さ` を確認し、1 回だけ見せて確かめます。指定が無ければ「目的先行・精読で読みます」と伝えてから始めます。
2. **読む論文を 1 本決める。** 依頼文に論文の番号があればそれを、無ければ範囲の節点と結び付いている論文から 1 本を選びます。決まらないときは手を付けずに候補を見せます。
3. **本文を読む。** `sai-moon-paper content paper <番号>` で本文を読みます。`深さ: 抄録` では題名・要旨・結論・限界だけに絞ります。図が要る深さ（`図` と `精読`）では `sai-moon-paper figures` の出力を使い、論の順番と図の関係を確かめます。
4. **型ごとの順番を守る。**
   - **目的先行**では、節点の項目ガイドにある「抜き出す項目」を問いにして、問いごとに論文を照らし合わせます。書く順番は「節点と問い → 論文の該当箇所 → 分かったこと」です。
   - **目的後付け**では、前半を論文だけで読み、問い・方法・結果・限界の要約を先に書き終えます。**木を見る前に要約を書き終えます。** 書き終えてから MCP の `sci_context`（`scope: "path"`。pi では `sai-moon-paper sci context --run "$SAI_PARENT_RUN_ID" --scope path`）で木を取り寄せ、後半で要約と木を照らします。どの節点にも合わなければ、`exclude` か保留の提案を出し、保留の理由を report に書きます。
5. **見つかったものを 4 段で整理する。** 読み終えた内容を、節点に加えていく読み・問いを深める読み・節点が揺れる読み・まだ決着が付かない読みの 4 段（①〜④。段の区分は sci-core の決まりに従う）に整理します。
6. **知見を証拠付きで書く。** `add_finding` で 1〜3 文にまとめ、`cites` に `#<番号> §<節>` か `#<番号> Fig.<番号>` の形で出典を付けます。数字を含む文には必ず出典を付けます。論文との結び付きは `link`（役割付き）で出し、読み終えたものは `read_state: read` にします。反映済みにする操作は利用者が行います。
7. **問いと候補を出す。** ほかの節点と結び付くなら `link`、新しい問いが出たら `add_question`、新しい選択肢が出たら `add_option`、対象から外れる論文は `exclude` で提案します。どれも提案のまま出し、木には触れません。
8. **利用者に仕分けてもらう。** 提案を出したら一覧を見せ、報告します。木に触れる操作は利用者が行うので、自分では実行しません。利用者が問いに答えたら、その内容を `answer_question` で記録します。

## 評価の観点
- 型が守られているか。目的後付けで、木を見てから要約を書いていないか。
- 知見が 1〜3 文に収まっているか。出典（`#番号 §節` か `Fig.<番号>`）が数字の付いた文にちゃんと付いているか。
- 論文に書かれていないことを推測で埋めていないか。読めなかった箇所はそのまま「読めなかった」と書いたか。
- 主張と根拠の対応が示されているか。根拠の強さ（関連・予測・因果・検証のどれか）を区別しているか。
- 図を見たときは、図の内容と著者の解釈を分けているか。
- 木に照らした結果が、どの節点のどの問いに対する返答になっているか。照合できないまま「関係あり」で済ませていないか。
- 提案に理由が付いているか。採点せずに、利用者に渡しているか。

## 出力の形
report は次の見出しで、この順のまま書きます。

```markdown
## 読んだ論文と深さ
## 論文だけの要約（目的後付けのときは木を見る前に書く）
## 木に照らして分かったこと
## 一致表
## 提案したこと
## 範囲外のメモ
```

- **読んだ論文と深さ** — 論文の番号と題名、読んだ深さ（抄録 / 図 / 精読）、使った型（目的先行 / 目的後付け）を書きます。
- **論文だけの要約** — 問い・方法・結果・限界の 4 点を、論文の中だけで書きます。目的後付けのときは木を見る前に書きます。目的先行のときは「問い → 該当箇所 → 分かったこと」の順に書きます。
- **木に照らして分かったこと** — 照らした節点と問いごとに、知見を 1〜3 文で書きます。どの節点にも合わなかった場合は、その旨と外す・保留の理由を書きます。
- **一致表** — 対象・データの型・出力の型・制約の列を持つ表を書き、各行に「一致・部分・不一致」と根拠を書きます。点数は付けません。根拠は知見の ID を添えます。
- **提案したこと** — 提案 ID（`P<数>`）と op 名、短い理由の表を書きます。
- **範囲外のメモ** — 範囲の外だと分かったことを、実際に書きます。保留した理由もここに残します。
