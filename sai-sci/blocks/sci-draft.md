# ✍ 文を書く

## 役割
「今回の SCOPE」の NODE が WRITE の ITEM のときに使う。背景や新規性の主張や、取り入れるときの書き方のような文を、利用者と往復して書く。

このブロックは一人で書き上げない。最初に 1 案を出したら、直したい点を 2〜3 問で聞いて、利用者が答えたところを反映して書き直す。

文の中に事実を書くときは、必ず出典を付け、その根拠を FINDING（`add_finding`）として別に PROPOSAL にする。出典の無い事実を文に入れない。書けない部分は空で埋めず、「今は書けない」と書く。BLANK とは書き分ける。

共通は次のとおり。出典は `literature-hard-rules` に従い、木・mind.md・state.md・tree.md を直接書き換えず、成果はすべて PROPOSAL で出す（木に触れる操作は利用者が行う）。

### 手順
1. **書く対象を確かめる。** SCOPE の NODE から、書くもの（背景 / 新規性の主張 / 取り入れ方など）を 1 つに絞ります。複数あるときは利用者に選んでもらいます。
2. **根拠を先に集める。** 文で使う事実を、FINDING としてまとめておきます。出典の無い事実を文に入れることはありません。
3. **1 案を書く。** 集めた根拠（あった分だけ）を使って、まず 1 案を書きます。
4. **直す点を 2〜3 問で聞く。** 次のどれかから問いを 2〜3 個だけ選び、答えを待ちます。
   - 冒頭の一文で、その NODE について何をしたいのかが分かるか。
   - 新しい点は、何と何を比べて違いとして書けているか。
   - 誰のどの判断に効くのかが書けているか。
   問いを増やしすぎないこと。答えはそのまま次の節に残します。
5. **背景のときは 4 点で確かめる。** 背景を書くときは、次の 4 点を 1 文ずつで答えられているか確かめます。
   - 今何をしようとしているか。
   - 今はどうなっているか。
   - 何が新しいか。
   - 誰が気にするか。
   答えられない点は、埋めずにそのまま報告します。
6. **改訂版を書く。** 利用者の答えを反映して書き直します。変えた点は 1 つずつ、理由ごと残します。
7. **文を PROPOSAL として出す。** 書いた文は `edit_text` で PROPOSAL にします（REVIEW_OP（TRIAGE 待ち））。文のタイトルは NODE の名から取ります。根拠になった事実は `add_finding`（出典付き）、書きながら生じた QUESTION は `add_question` で PROPOSAL にします。
8. **利用者に TRIAGE してもらう。** PROPOSAL を出したら一覧を見せ、報告します。採用と却下は利用者が行います。

## 評価の観点
- 1 案を出してから、直したい点を 2〜3 問で聞いたか。一人で書き上げていないか。
- 文中の事実の全部に出典（`#<番号> §<節>`）が付いているか。根拠が別の FINDING の PROPOSAL として出ているか。
- 背景のときは、上記 4 点がそれぞれ 1 文で答えられているか。答えられない点を空で埋めていないか。
- 新規性の主張が、何と何を比べて違いとして書かれているか。「新しい」とだけ書いていないか。
- 書けないものを BLANK や推測で埋めていないか。
- 改訂した点と、その理由が 1 つずつ残っているか。
- 文の PROPOSAL が `edit_text` として出ているか。

## 出力の形
report は次の見出しで、この順のまま書きます。

```markdown
## 書いた文
## 直した経緯
## 根拠
## PROPOSAL
## OUT_OF_SCOPE
```

- **書いた文** — 最終的な文を書きます。どの NODE のための文かを上に書き、文のタイトルも添えます。
- **直した経緯** — 聞いた問い、利用者からの答え、変えた点、変えた理由の表を書きます。
- **根拠** — 文の中で使った事実を、FINDING の ID（`F<数>`）・POLARITY・出典（`#<番号> §<節>`）の表で書きます。根拠の無い箇所があれば、そこを指摘します。
- **PROPOSAL** — PROPOSAL の ID（`P<数>`）と op 名、短い理由の表を書きます。
- **OUT_OF_SCOPE** — SCOPE の外だと分かったこと、書けなかった点、保留した理由を書きます。
