# EXISTING

この Q では、既存手法を並べる。並べるのは手法の名前だけではない。入力が何か、出力が何か、どんな条件で測られているか、まで並べてはじめて骨組みに使える。1 つ 1 つに代表になる論文を結び付け、この分野の手法がどう並んでいるかを描ける状態にする。

研究を設計するとき、最初に埋めるのはここである。ここが空だと、課題も手法も新規性も、比べる相手が決まらないまま先に進んでしまう。

「網羅できた」と認められるのは、次の両方を満たしたときである。O ができたあとの検索が 2 回以上あり、そうしても新しいカテゴリが出てこないこと。そして、CANDIDATE と SELECTED のすべての O に、代表例としての論文が 1 本以上あること。どちらかが欠けているあいだは「まだ探しきられていない」と考える。O を足しているだけの段階では埋まったと見なさない。

## Q
この分野の既存手法には何があるのか。

## Child Q
- 自分がやろうとしていることを、すでに誰が何で解いているか。
- その中で、自分の対象と条件にいちばん近いものはどれか。
- 手法の種類で分けると、どの種類が厚くて、どの種類がまだ空いているか。

## Extract
- 手法の名前・カテゴリ・入力と出力・評価に使ったデータ・主な性能
- 比べた相手・差の大きさ・条件

## Pitfall
- 分野名や手法名のリストだけで、代表になる論文を 1 本も決めていない。
- 手元の Library に無いことを、そのまま「この分野では新しい」と読み替える。ここは、あたらしさを測る場所ではない。
- 近い分野まで広げた勢いで、自分の対象や条件に合わない手法が混ざって並ぶ。
- 中心の分類を 1 つに決めて周辺の手法を捨てている。あとから増やすと分類の組み直しになる。
