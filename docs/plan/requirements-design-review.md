# 要件定義書: agent-link の設計の見直し（機能は保ったまま）

## 何を

複数のアプリ（sai-tree → sai-link＋Web → agent-link）を経て今の形になった agent-link を、**機能は 1 つも変えずに**、設計全体（層・境界・契約・命名・配布・設定）見直す。

見直すものと見直さないもの:

| 見直す | 見直さない |
|---|---|
| もう無い物（TUI・herdr・sai-phone）の**名前と置き場** | 機能（run・カード・文書・子タスク・daemon・Workflow・History・cc の起動）の追加と削除 |
| 文書と実装の**食い違い** | 画面の作り（素の JavaScript）と依存（FastAPI・標準ライブラリ） |
| **契約**の置き場所（1 枚に集める） | 契約の中身（終了コード・`--json` の約束・Web が読む JSON の項目） |
| 設定の**形**（環境変数 → 設定ファイル。環境変数は上書き） | 入口の守り（127.0.0.1 の待ち受けと `require_internal`。合言葉は戻さない） |
| **入れ方・点検・消し方**（install 相当・doctor 相当・uninstall 相当） | データの置き場（`~/.agent-link` のまま。移さない） |

## なぜ

- agent-link は**複数のアプリを経てきた**ため、もう無い物の名前と理由がコードと文書に残っている。
  - TUI と共有するために切り出したクレート（TUI は無い）、herdr（消えた多重化）、sai-phone（消えた製品）。
- そのため、**文書と実装が食い違う所がある**（現在 6 件。`docs/contract.md` §7）。とくに、現役のコードのコメントが、
  もう無い命令を指している（コメントを信じると必ず失敗する）。
- **「過去の決定」と「現在の仕様」が同じ文書に混ざっている**ため、決定が古くなっても気づけない。
  例: `docs/plan/requirements.md` の完了条件に残る合言葉（`AGENT_LINK_WEB_TOKEN`）は、その後の簡素化でやめた物である。
- 入れ方がソースからの手作業で、点検（自分で状態を確かめる命令）と消し方が無い。

## 決定事項と理由

| 決定 | 理由・補足 |
|---|---|
| **機能は 1 つも変えない** | 見直しの目的は形の整理。機能を動かすと、原因の切り分けができなくなる |
| データの置き場は `~/.agent-link` のまま。移さない | 利用者の選択（決定済み） |
| 入口の守り（127.0.0.1 の待ち受け・合言葉なし・`require_internal`）は変えない | 利用者の選択（決定済み） |
| 文書を「変わらない物（考え方・不変条件）」「契約」「過去の決定」に分ける | 変わる速さが違う物を混ぜない。今回の食い違いはこれで防ぐ |
| 「中だけで使う名前（`saiApi`・`sai_home()` など）は変えない」という過去の決定を、**見直しの対象**として扱う | 当時の理由は「外から見えない。差分が増えるだけ」。**変えるなら決定のやり直し**になる |
| 契約の名前（`sai-progress` など）は**公開する前に**片付ける | 公開後は他人の環境に焼き付き、互換を保つ義務が生まれる |
| 本物のプロジェクトでの確認はしない（一時フォルダで行う） | 利用者の環境と、動いている Web（8400 番）を変えないため |

未決（見直しの中で利用者と決める）:

- 配布の形（1 行の入れ方と、言語の登録簿のどちらを入口にするか）。
- 設定ファイルの場所と名前。
- 「中だけで使う名前」を変えるか、規則（`AGENTS.md` の `sai` の接頭辞）ごと見直すか。
- Web の常駐の自動起動を既定にするか（`launchd` を持たない決定の再検討）。

## 完了したときに利用者が確かめられること

1. **機能が 1 つも減っていない。** 見直しの前後で、CLI の命令の一覧（`agent-link schema --json` の `commands[]`）と
   Web の住所の一覧が同じである。
2. **文書と実装が一致している。** 現在の設計の文書と、契約の文書がある。食い違いの一覧が空である。
3. **もう無い物の名前が、説明から消えている。** 「Web と CLI が使う組み立て処理」「herdr バイナリを呼ぶ」のような、
   実態と違う説明が無い。現役のコードのコメントが、現役の命令だけを指している。
4. **入れ方と消し方が 1 つずつある。** 一時フォルダで「入れる → 点検する → 消す」が通り、
   利用者の環境（`~/.agent-link`・シェルの設定・`~/.local/bin`）と、動いている Web を変えない。
5. **設定をファイルででき、環境変数で上書きできる。** 環境変数だけで動く経路も残っている（CI を壊さない）。
6. **過去の決定が、日付と理由つきの記録として残っている。**
7. **テストが全部通る。** 命令は `AGENTS.md` の「テストと確認」と同じ（Rust・Web の JS・Web の Python）。

## 範囲外（今回はしない）

- 機能の追加と削除（新しい画面・新しい命令・新しい block）。
- Docker 化、多人数・クラウド・ログイン、エージェントの道具（MCP）の追加、端末の画面（TUI）の復活、
  crates.io での公開、Linux への対応。
- 実行エンジンの**振る舞い**の変更（実行の仕方・DB の形・書き出しの項目を変えること）。
- データの移行（古い `.agent-link/`・`.sai/`・`~/.sai` を読む互換の処理）。
- 本物のプロジェクトでの `agent-link init`（`--update` を含む）。確認は一時フォルダで行う。
- sai-moon・sai-tree のリポジトリを直すこと（読み取り専用）。
