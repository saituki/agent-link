# 作業報告書と task_report の書式（doc-report）

## 作業報告書

親がくわしく知りたいときに読む報告である。親はまず `task_report` の短い報告を読み、必要なときだけこれを読む。

- ファイル名: `report-<ID>.md`（追加指示のあとは `report-<ID>-r2.md`）
- description: `作業報告書 <ID>: <結果>、<要約>`

```markdown
# 作業報告書 <ID>: <件名>

## 結果
DONE | PARTIAL | BLOCKED

## 実装計画書
waggle:<受け取った計画書のトークン>

## 変更
| ファイル | 内容 |
|---|---|
- コミット: `<hash>`（ブランチ `<branch>`、作業用コピー `<path>`）

## 完了条件の確認
- [x] AC1: <確かめた方法と結果>
- [ ] AC2: <満たせなかった理由>

## 検証の結果
<実行したコマンドと出力の要点。失敗したものも書く>

## 計画との違い
<計画どおりにしなかった点と理由。計画の前提がコードと違った点>

## 親への申し送り
<統合で気をつけること、他の作業への影響、共有契約を変える必要があると思う点、残った課題>
```

## task_report

`report` は 10 行以内で、次の形にする。

```
結果: DONE | PARTIAL | BLOCKED
要約: <何をしたか 1 文>
コミット: <hash>（<branch>）
完了条件: AC1 済 / AC2 済 / AC3 未（理由）
問題点: <無ければ「なし」>
親への依頼: <判断してほしいこと。無ければ「なし」>
```
