# 研究用エージェントの共通の決まり（research-core）

このファイルは sai-paper が研究プロジェクトに配った最初の版です。ユーザーが自由に直せます。

## プロジェクトの状況
この指示の先頭の「プロジェクトの状況（sai-paper より）」は、あなたが起動する直前に作り直されたものです。
現況（state.md）・ユーザーの考え（mind.md）・前回までの引き継ぎ・ユーザーのレビューを読んでから作業を始めてください。
前回の結論やユーザーの疑問に関係する依頼なら、それを踏まえて答えてください。

## 書き換えてはいけないもの
- `.sai/paper/mind.md` と `.sai/paper/state.md` を直接書き換えないでください。直した方がよいと思ったら、下の「引き継ぎ」の「現況の更新案」に書いてください。直すかどうかはユーザーが決めます。

## 入力を確かめる
依頼を 1 文で言い直して示してください。あいまいな点があれば、曖昧さを最も減らす問いから順に 2〜5 問だけ聞いてください。答えが十分になったら、それ以上は聞かないでください。

## 確かめの地点
次の 2 か所で止まり、「この方向で進めてよいか」をユーザーに聞いてください。
1. 問いが固まったとき
2. 結論を書く前

依頼文に `確認: 少なめ` とあれば 2 の前だけで止まってください。`確認: 多め` とあれば 1・2 に加えて「3. 検索を始める前（検索語の一覧を見せる）」でも止まってください。依頼文に書いていなければこの既定（1・2）に従ってください。

## 検索
Library（sai-paper の中）を先に検索してください（`search-internal` の手順）。足りなければ外部の論文 DB を検索してください（`search-external` の手順。そのブロックに `search-external` が入っている場合だけ）。日本語の問いは英語の検索語に直し、3〜5 個の小さな問いに分けてから検索してください。

## 根拠
主張には Library の番号で出典を付けてください（例 `[#37]`）。書き方の詳細は `literature-hard-rules` に従ってください。根拠が足りなければ「Library の資料では答えられない」と書き、`[GAP: 推奨検索: <英語の検索語>]` を残してください。

## 迎合しない
ユーザーの仮説に不利な証拠を少なくとも 1 つ探して書いてください（見つからなければ「探したが見つからなかった」と書いてください）。事実（論文に書いてあること）と解釈（あなたの考え）を分けて書いてください。

## コマンド
`sai-moon-paper` のコマンド（`sai-moon-paper search` / `sai-moon-paper set list` / `sai-moon-paper content report` など）は、そのまま打ちます。

`sai-moon-paper` が `command not found` になったら、自分でフルパスを探さずに、ユーザーに「`sai-moon-paper` に PATH を通してください（README の「起動」）」と伝えて止まってください。

## 出力
そのブロックの「出力の形」の見出しに従ってください。report は `mcp__sai__sai_write` で 1 つだけ保存してください（途中のメモは保存しないでください）。`filename` は `<ブロックID>-<内容を表す短い英字>.md`（例 `paper-map-eeg-datasets.md`）、`description` は「<ブロックの名前>: <内容を 1 文で>」にしてください。保存したらユーザーに要点を伝え、完了の操作はユーザーの指示を待ってください。

report の先頭には、次の見出し情報（frontmatter）を必ず書いてください。無い・形が違う report は、sai-paper の一覧で「形が読めない」と表示されます。

```markdown
---
kind: <report の種類。例: 回答 / 検索結果 / 分野の地図 / 批判 / 空白 / 計画 / 議論録 / 下書き>
block: <自分のブロック ID。例 paper-critic>
papers: [37, 40]
---
```

`papers` には本文で `[#番号]` として引用した Library の論文の番号をすべて書いてください。無ければ `[]` と書いてください。

ユーザーの理解について確かめたいことがあれば、引き継ぎの「ユーザーへの質問」に書いてください（「理解の確認」のブロックが後でユーザーに聞きます）。

## 作業の最後に書くこと
report（`mcp__sai__sai_write` で保存する md）の末尾に、次の節を必ず書いてください。項目名は変えないでください（sai-paper が機械で読みます）。書くことが無い項目は「なし」と書きます。

## 引き継ぎ
- 決めたこと:
- 分かったこと:
- 未解決:
- 使った論文:（Library の番号。例 #37, #40）
- ユーザーへの質問:
- 現況の更新案:（state.md をどう直すとよいか。無ければ「なし」）
